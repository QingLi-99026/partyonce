# PartyOnce Stage 2 Step 8.1 Order Skeleton Plan

Date: 2026-05-11

Scope: planning only

## 1. Planning Boundary

Step 8.1 plans the Order skeleton that should follow the completed Stage 2 Lead and Quote admin workflow.

This document does not implement code, migrations, database changes, frontend changes, payment, Stripe, webhook/n8n, external messaging, deployment, or production configuration changes.

The entry condition is:

```text
Persistent Lead
-> accepted Quote
-> draft Order skeleton
```

The Order skeleton must not be treated as payment readiness. It is a business record and workflow planning step only.

## 3. Order Skeleton Principles

The Order skeleton must follow these rules:

```text
Order can only be created from an accepted Quote.
Order must keep quote_id and customer_id.
Order must copy key event, selection, pricing, and customer snapshots from the accepted Quote.
Order starts as draft unless owner approves a pending_deposit state later.
Order does not collect payment.
Order does not call Stripe.
Order does not trigger webhook/n8n.
Order does not send email/SMS/WhatsApp.
Order does not assign suppliers automatically.
Order does not create contracts.
```

The Order skeleton exists to let operations see that an accepted Quote has moved into a booking/work execution placeholder.

## 5. Order Status Contract

Recommended minimal statuses:

```text
draft
pending_deposit
confirmed
in_progress
completed
cancelled
```

Status meaning:

```text
draft: Order skeleton created from an accepted Quote; no payment collected.
pending_deposit: future state only until payment planning is approved.
confirmed: operations has manually confirmed the booking without implying payment integration.
in_progress: event preparation or execution is underway.
completed: event has been completed.
cancelled: order is cancelled or abandoned.
```

Step 8 implementation should initially allow:

```text
draft
confirmed
in_progress
completed
cancelled
```

`pending_deposit` should remain a placeholder unless owner approves a deposit/payment step. If included in the enum, it must be documented as non-payment behavior.

## 6. Quote to Order Boundary

Order creation preconditions:

```text
Quote exists.
Quote status is accepted.
Quote has customer_id.
Quote has lead_id.
Quote has final_total.
Quote has line_items_json and selection_snapshot_json snapshots.
No existing Order already exists for the Quote in skeleton phase.
Requester is admin/manager.
```

Order creation must not:

```text
create payment intent
create checkout session
trigger Stripe
change deposit_status to paid
send customer notification
send supplier notification
trigger webhook/n8n
generate contract
```

Quote status handling:

```text
After Order skeleton creation, Quote may move to converted_to_order in the same transaction.
If this is implemented, converted_to_order must remain backend-controlled and not directly selectable in the admin Quote UI.
If Order creation fails, Quote status must remain accepted.
```

Recommended strategy:

```text
Create Order and update Quote to converted_to_order in one transaction.
Do not expose converted_to_order as a direct PATCH status until Order skeleton exists and is verified.
```
