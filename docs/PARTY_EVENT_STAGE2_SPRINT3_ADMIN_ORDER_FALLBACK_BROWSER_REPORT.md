## 3. P0 Fallback Fix

Sprint 2 issue:

```text
If local API PATCH failed and the backend Order id did not exist in mock seed data, fallback update could return null.
That could leave the UI unable to show an updated Order object.
```

Sprint 3 fix:

```text
frontend/vue-app/src/mock/adminOrders.js now supports fallback upsert behavior.
updateAdminOrderSkeleton(orderId, patch, base) creates a local fallback Order when the id is missing.
The generated fallback Order preserves available base data when present.
If no base data exists, it creates a minimal local-only Order shape.
Status flow is rebuilt after status changes.
```

Service behavior:

```text
frontend/vue-app/src/services/adminOrderService.js now returns mixed fallback after API PATCH failure.
If API detail load fails and the id is not in mock seed, the service creates a generated fallback detail Order instead of returning null.
```

Fallback source labels:

```text
local API
fallback mock
mixed fallback
```
