## 2. Current Storage Basis

Accepted Step 5 migration:

```text
backend/migrations/001_create_lead_storage.sql
```

That migration intentionally creates only:

```text
customers
leads
follow_ups
```

It explicitly does not create Quote or Order tables.

Step 6.4 therefore plans the next storage layer for:

```text
quotes
```

The first Stage 2 Quote skeleton should use `line_items_json` instead of creating `quote_items`.

## 3. Design Decision

Recommended first implementation:

```text
Create one quotes table.
Store quote line items in line_items_json.
Store the quoted selection in selection_snapshot_json.
Require lead_id and customer_id.
Do not create quote_items table yet.
Do not create orders table.
Do not create payment tables.
```

Reason:

```text
Stage 2 is validating Lead-to-Quote workflow, not full quote item editing.
line_items_json matches the accepted snapshot-first Lead storage approach.
It keeps the first Quote migration small and reviewable.
It avoids coupling Step 6 to pricing engine finalization.
```

Future expansion:

```text
quote_items can be added later after item-level backend editing and pricing rules are accepted.
```

## 4. Quotes Table Purpose

The `quotes` table stores admin/manager-created draft proposals from persistent Leads.

It must support:

```text
Quote created from existing Lead
Quote linked to Customer through Lead.customer_id
server-side snapshot of selection and line items
Quote status lifecycle through draft/sent/accepted/rejected/expired
future converted_to_order status without creating Order in Step 6
```

It must not support in this step:

```text
anonymous quote creation
direct quote creation from localStorage
Order creation
payment state
Stripe references
webhook/n8n state
external message state
```

## 6. Status Constraint

Allowed status values:

```text
draft
sent
accepted
rejected
expired
converted_to_order
```

Implementation rule for Step 6:

```text
converted_to_order may exist in the schema for forward compatibility.
API must block setting converted_to_order until Order work is approved.
```

Reason:

```text
The database can safely recognize the future state, but application behavior must not create Order.
```

## 7. Foreign Keys

Required foreign keys:

```text
quotes.lead_id -> leads.id
quotes.customer_id -> customers.id
```

Recommended delete behavior:

```text
Do not cascade delete Quote when Lead or Customer is deleted.
Prefer no hard delete in normal app flows.
Use status/archive semantics later if needed.
```

`created_by_user_id`:

```text
Do not add FK in the first draft unless users.id relationship is confirmed for local/staging profile.
Keep integer field as nullable until auth model is reviewed.
```

## 9. Draft SQLite SQL

This is draft SQL text only. It is not added to `backend/migrations` in this step.

```sql
-- PartyOnce Stage 2 Step 6.4 draft only
-- Migration draft: 002_create_quote_storage
-- Scope: persistent Quote storage only.
-- Safety boundary:
--   - Do not run against production without owner approval.
--   - Does not create Order tables.
--   - Does not add payment, Stripe, webhook, n8n, or outbound messaging tables.
--   - Intended first target: local/staging SQLite after review.

PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS quotes (
    id INTEGER PRIMARY KEY,
    lead_id INTEGER NOT NULL,
    customer_id INTEGER NOT NULL,
    quote_number VARCHAR(80) NOT NULL,
    status VARCHAR(40) DEFAULT 'draft' NOT NULL,
    currency CHAR(3) DEFAULT 'AUD' NOT NULL,
    subtotal DECIMAL(12, 2) DEFAULT 0.00 NOT NULL,
    discount_total DECIMAL(12, 2) DEFAULT 0.00 NOT NULL,
    tax_total DECIMAL(12, 2) DEFAULT 0.00 NOT NULL,
    final_total DECIMAL(12, 2) DEFAULT 0.00 NOT NULL,
    line_items_json TEXT,
    selection_snapshot_json TEXT,
    valid_until DATETIME,
    sent_at DATETIME,
    accepted_at DATETIME,
    created_by_user_id INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP NOT NULL,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT uq_quotes_quote_number
        UNIQUE (quote_number),
    CONSTRAINT fk_quotes_lead_id
        FOREIGN KEY (lead_id)
        REFERENCES leads (id),
    CONSTRAINT fk_quotes_customer_id
        FOREIGN KEY (customer_id)
        REFERENCES customers (id),
    CONSTRAINT ck_quotes_status
        CHECK (status IN (
            'draft',
            'sent',
            'accepted',
            'rejected',
            'expired',
            'converted_to_order'
        )),
    CONSTRAINT ck_quotes_currency
        CHECK (length(currency) = 3)
);

CREATE INDEX IF NOT EXISTS idx_quotes_lead_id
    ON quotes (lead_id);

CREATE INDEX IF NOT EXISTS idx_quotes_customer_id
    ON quotes (customer_id);

CREATE INDEX IF NOT EXISTS idx_quotes_status
    ON quotes (status);

CREATE INDEX IF NOT EXISTS idx_quotes_created_at
    ON quotes (created_at);

CREATE INDEX IF NOT EXISTS idx_quotes_lead_status
    ON quotes (lead_id, status);

CREATE INDEX IF NOT EXISTS idx_quotes_customer_status
    ON quotes (customer_id, status);
```

## 10. Mapping From Lead To Quote

When later API code creates a Quote:

```text
leads.id -> quotes.lead_id
leads.customer_id -> quotes.customer_id
generated quote number -> quotes.quote_number
default draft -> quotes.status
request currency or AUD -> quotes.currency
validated pricing subtotal -> quotes.subtotal
validated discount total -> quotes.discount_total
validated tax total -> quotes.tax_total
validated final total -> quotes.final_total
request line items or derived line items -> quotes.line_items_json
leads.selection_snapshot_json plus request override -> quotes.selection_snapshot_json
request valid_until -> quotes.valid_until
current admin/manager id -> quotes.created_by_user_id
```

Lead update after successful Quote insert:

```text
leads.status may become converted_to_quote
only after Quote insert succeeds
within the same transaction
```

## 11. Validation Rules For Later API

Future `POST /api/quotes` should validate:

```text
lead_id exists
lead belongs to existing customer
Lead status is not unqualified or closed
currency is 3 characters
totals are non-negative
line_items_json is valid JSON if supplied
selection_snapshot_json is valid JSON if supplied
```

Recommended Lead status gate:

```text
allow qualified by default
optionally allow contacted for local/staging demo only
block unqualified
block closed
```
